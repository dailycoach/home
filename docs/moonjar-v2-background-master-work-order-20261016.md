## 00. 역할 및 원칙

당신은 미술감독, 도자기 재질 디자이너, 프론트엔드·SVG/Canvas 개발자, 접근성 QA, 개인정보 QA다. 추상적인 기획으로 끝내지 말고 디자인 마스터·투명하게 재현 가능한 출력물·기존 작품 호환성·검증 자료를 실제로 납품한다.

이미지 출처: 자개 원본 8종/파생 96종과 기존 달항아리 바탕 2종은 운영자가 자체 제작 사실을 확인했다. **국립중앙박물관 사진을 새 이미지에 삽입하거나 특정 소장품 사진을 추적·복제하지 않는다.** 조선 백자의 일반적인 조형 어휘를 바탕으로 DAILYCOACHING 오리지널 도안으로 새로 그린다.

코칭 서사: `도착 → 그릇 → 자개 → 만남 → 전환 → 이름 → 돌아감`; DAILY(Detect / Acknowledge / Inquire / Link / Your Action). 진단/성격 판독/정답 배치 금지. 자개 안과 밖의 자유로운 배치를 유지한다.

## 01. 제품적 정의

**제품명** 빛을 담는 달항아리 — 나를 담고, 다시 보다  
**이번 목표** 종이에 그려놓은 회색 윤곽선을, 자개가 돋보이면서도 스스로 아름다운 **유백색 도자기**로 만든다. 전환은 기존 기록·작품을 해치지 않는 방식이어야 한다.

**최종 아트디렉션 문장**

> 흙에서 온 그릇은 조용히 빛을 받는다. 자개는 그 위에서 저마다 빛난다. 달항아리는 작품의 주인공이지만 자개의 선택을 방해하지 않는다.

무작정 질감/금박/네온을 넣지 않는다. 백자의 불규칙성은 '결함'에 대한 도덕적 교훈이 아니라 제작 방식의 시각적 맥락이다.

## 02. 현재 배경의 실제 한계

현행 `canvas_light.png`와 `canvas_dark.png`는 각각 1600×1800 PNG, 약 74/83KB이며 같은 형태의 얇은 선화다. 원본 도안에서 본체 내부는 배경과 구분되기 어렵고, 입구가 넓으며, 목·어깨·몸통의 변화가 기계적이다. 밝은 자개가 흰 바탕과 겹쳐 보일 수 있고, 어두운 바탕에서는 *유백색 항아리*보다 어두운 바탕의 선이 강조된다. 눈에 보이는 재질 표현과 배경의 상·하 여백 비례를 적극 보완한다.

### 반드시 보존할 데이터 계약
- 논리 영역 **1600×1800, 8:9, 원점 왼쪽 위, 자개 중심 좌표 x/y**.
- 원본 **자개 PNG 96개 + WebP 썸네일 96개** 모두 손대지 않는다.
- scene의 x/y, width/height, rotation, locked, notes, snapshots, theme, free placement.
- 프로젝트 JSON·IndexedDB·작품 PNG·카드 1600×2400의 이전 호환.
- 구형 `templateId: outline-v3`, `schemaVersion: 1.0.0`, `assetPackVersion: moonjar-png-v3`인 문서가 계속 복원되고 원래 모습을 보여야 한다.

### 03-B. 톤과 물성

**Daylight Porcelain (기본)**: 종이 바탕은 따뜻한 #F6F3ED 주변, 백자 본체는 대략 RGB 233~250 범위에서 흰빛이 살아 있게 구성. 좌상단에 넓은 확산광, 우하단/굽에 부드러운 그림자. 텍스처는 중앙부의 자개를 누르지 않아야 한다.

**Moonlit Porcelain (야간)**: 주변 배경은 네이비 먹색 #12232A 계열. 가장 중요한 것: **어두운 종이 속에서도 백자 본체는 유백색 물질로 보인다.** 기존처럼 항아리 안쪽이 종이색과 같은 검은 구멍이 되면 불합격. 청록·보라 자개는 색을 유지하며 지나친 푸른 색번짐 금지.

**가급적 하지 말 것**: 노란 수묵 배경, 전면 펄 텍스처, 금칠, 배경에 이미 자개 완성 패턴 인쇄, 꽃·산수·성격 해석 상징, 과한 원근감.

### 03-C. 3개 표현 레벨
- **Core / P0**: Daylight, Moonlit 2종의 공통 오리지널 마스터를 완성. 실루엣이 같은 인쇄형 2D 백자.
- **Accessibility / P1**: 고대비 또는 표면 노이즈 낮춘 보조 버전. 별도로 선택할 수 있고 작품 표현의 우열을 뜻하지 않는다.
- **Print / P2**: 잉크 절약형 및 흑백 복사 친화형. PDF/학교용 전자책에서 사용. Core와 섞어 사용자를 혼란스럽게 하지 않는다.

## 05. 저장본 호환 및 렌더링 아키텍처 (가장 중요한 P0)

### 두 단계 운영 권장
**WAVE 6A: 빠르고 안전한 재질 패치**는 구형 윤곽선과 좌표를 1:1 보존한 텍스처/음영 오버레이를 별도 시안으로 만든다. 기존 이미지 바이너리는 손대지 않고 V2를 선택한 작품에만 보여준다.

**WAVE 6B: 완전한 새 조형**은 입구·어깨·배·굽 비례를 새로 그린 V2로 만들되, **기존 사용자 작품에는 자동 적용하지 않는다.** 기존 자개 위치가 시각적으로 재해석되는 일을 막기 위한 결정이다.

### 엄격한 데이터 계약
현행 scene은 `templateId = outline-v3`, `theme = light|dark`이고 schema는 `additionalProperties:false`. 따라서 `canvasVariant`를 앱 상태에 무작정 넣으면 저장검증에서 거부된다.

권장 방식:
1. 새 디자인 선택 값은 **scene 내부의 optional `canvasVariant`** 로 추가하되, 없는 경우에는 `legacy-outline-v3`으로 해석한다.
2. 신규 프로젝트 기본값은 `porcelain-v2`. 단, 기존 작업 가져오기는 바탕 변경을 **명시 선택할 때만** 수행한다.
3. `templateId`의 'outline-v3' 기존 값을 신버전으로 일괄 교체하지 않는다. 신규 templateId가 필요하면 schema union/명시 마이그레이션과 구버전 파서 테스트를 만든다.
4. `snapshots[].scene`에도 동일한 캔버스 식별자가 있어야 한다. 기존 스냅샷의 바탕/조각 위치 보존.
5. `data/schema.json`, `data/empty.json`, `src/domain.js`, `src/rendering.js`, `src/app.js`를 **같은 PR**에서 동기화한다. export card가 다른 배경을 사용하면 불합격.
6. 기존 `assets/canvas_light.png`, `assets/canvas_dark.png`는 배포에서 최소 한 시즌 이상 보존하고 기존 `.moonjar.json`에서 사용 가능하게 유지한다.
7. 모든 신규 이미지의 원본 SHA-256·파일 크기·해상도를 manifest 또는 별도 `variants.json`에 기록하고 `check-moonjar.mjs`로 검사한다.
8. 재현 가능성: **scene + asset version**으로 작품 모습이 결정되어야 하며, URL 캐시/테마 변경에 의존하지 않는다.

### 간략 구성도
```text
Saved Project JSON / old imports
  └─ scene { templateId, theme, canvasVariant? , nodes[] }
          ├─ resolveCanvasAsset(scene)
          │    ├─ missing variant -> legacy V3 (default for old files)
          │    └─ porcelain-v2 -> V2 day/night
          └─ single artwork renderer
               ├─ SVG editor
               ├─ snapshots/comparison
               ├─ PNG image
               ├─ personal postcard
               └─ print/PDF preview
```

**반드시 실제 파일 시스템에서 구형 파일을 새 버전으로 열고 저장하며 출력해 비교한다.** 테스트를 통과했다고 우측에 텍스트만 보고하지 말고 캡처/이미지 증빙을 남긴다.

## 06. 디자인 선택 UX

'바탕 비교'를 **'나의 달항아리 바탕'**으로 안내하되, 단순히 라디오 숫자를 늘리지 않는다.
- 상단에 *백자 낮 / 달빛 밤* 두 가지 커다란 미리보기와 한 줄 설명.
- 기존 작품에서는 '원래 바탕 유지'가 기본 선택. 새 바탕으로 바꾸면 **내 작품의 조각이 그대로 유지되는지 미리보기에서 확인하고 적용**한다.
- 원본 V3 모양을 보존하려면 선택지에 **기존 도안으로 보기**를 제공한다.
- 프린트/고대비 버전은 별도 메뉴로 묶어 기본 경험을 단순하게 유지한다.
- 사용자가 바탕을 선택한 감정·성격을 해석하는 문구를 넣지 않는다.

| BG-20 | 비저장 모드와 개인정보 | 원격 업로드 없음, 기존 개인정보 보호 설정 유지 |
| BG-21 | 옛 `.moonjar.json` JSON | 무상태 필드 누락 시 default 처리, 강제 migration 없음 |
| BG-22 | GitHub Pages 정적 경로·캐시 | 새/기존 자산 200, hash/theme 정확, 404 없음 |
| BG-23 | 스크린리더·키보드 | 배경의 의미 있는 이름/선택 상태 안내, 실기기 미검증 표기 |
| BG-24 | 권리·원본 아카이빙 | 두 도안 모두 자체 디자인, 신규 마스터 파일 제작 이력 등록 |

### 반려 사유 / Stop conditions
- 기존 작품의 자개 위치가 사용자의 선택 없이 달라짐.
- 배경을 바꾸자 오래된 JSON이 '허용되지 않은 버전'으로 거부됨.
- 야간 화면에서 백자 실체가 보이지 않음.
- 예쁜 이미지 때문에 자개를 배치한 위치와 텍스트 카드 출력이 잘림.
- '실제로 제작한 이미지' 없이 스톡 사진/타 기관 소장품 이미지를 대신 사용.
- 자개 96개 자체 디자인을 계속 '저작권 미확인'으로 보고.

## 08. WAVE 실행 순서와 검수 게이트

1. **G0 — 자산 확정**: 기존 PNG 2종 스크린샷/해시, 자개 96개 색상군, 문서 스키마 보존.
2. **G1 — 미술 시안**: Daylight/Moonlit 각각 빈 장면과 24개 자개 샘플. 형태·표면·배경 대비를 실제 이미지로 평가.
3. **G2 — V2 마스터 납품**: SVG/PNG/WebP 원본 및 브랜드 디자인 토큰. 확정 후 PNG 해시 생성.
4. **G3 — 데이터·렌더러**: 기존 저장본 보존/variant 라우팅/작품 카드 일관화. 이미지 파일만 덮어쓰지 않는다.
5. **G4 — 자동 QA**: 기존 단위·회귀·multi-engine + 본 문서 BG-01~BG-24 증빙.
6. **G5 — 사람의 디자인 검토**: 0/1/8/40/160조각, 밝기·크기별 결과를 디자이너·코치가 함께 검토.
7. **G6 — 실기기·접근성**: Android/iOS/인쇄, 큰 글씨, 미세 터치와 저장 복원.
8. **G7 — 배포 판단**: 사용자가 승인하기 전 `main` 병합/운영 배포하지 않는다. 배포 시 rollback 경로 마련.
