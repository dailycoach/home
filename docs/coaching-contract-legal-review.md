## 3. 코칭 윤리

- [ ] 첫 세션 전에 코칭의 성격, 역할, 비용, 일정, 종료권과 비밀보장 범위를 이해 가능한 언어로 설명했다.
- [ ] 고객이 목표와 진행 방식에 의견을 말하고 수정할 수 있다.
- [ ] 고객이 질문에 답하지 않거나 다른 전문가를 선택하거나 코칭을 종료할 수 있다.
- [ ] 코칭과 치료·상담·의료·법률·세무·투자 자문의 경계를 명확히 했다.
- [ ] 코치의 전문영역을 벗어나는 상황에서 외부 전문가 안내·중단 절차를 마련했다.
- [ ] 이해상충, 다중 역할, 추천 보상과 스폰서 관계를 투명하게 알린다.
- [ ] 자격·경력·서비스 효과를 정확히 표기하고 특정 성과를 보장하지 않는다.
- [ ] 차별·성희롱·성적 관계·착취적 관계 금지와 윤리상 우려 제기 채널을 검토했다.
- [ ] 고객과 제3자의 생명·신체에 관한 급박한 위험 등 비밀보장 예외를 국내 법령과 최소범위 원칙에 맞게 검토했다.

## 4. 개인정보 처리

계약 이행에 실제 필요한 정보는 「개인정보 보호법」 제15조제1항제4호에 따른 처리 안내와 선택 동의를 구분하는 방향으로 설계했다. 그러나 실제 항목별 필요성과 보유기간은 운영 전 확정해야 한다.

- [ ] 필수항목과 선택항목을 구분하고 각 항목의 필요성을 문서화했다.
- [ ] 이메일 OTP만으로 운영할 때 휴대전화번호를 필수로 받을 필요가 있는지 검토했다.
- [ ] 목표 입력은 한두 문장으로 제한하고 진단명·치료기록 등 민감정보 입력 금지 안내를 표시했다.
- [ ] 민감정보가 우발적으로 입력됐을 때 삭제·가림·재발행 절차를 마련했다.
- [ ] 계약·결제 기록과 세션 노트·대화 기록을 분리했다.
- [ ] 녹음, 전사, AI 요약, 연구, 익명 사례, 후기·홍보, 마케팅, 제3자 자료전달을 각각 분리했다.
- [ ] 선택 동의의 초기값이 모두 `DECLINED` 또는 `NOT_OFFERED`다.
- [ ] 선택 동의 거부가 기본 코칭 계약 체결을 막지 않는다.
- [ ] 열람·정정·삭제·처리정지 등 권리 요청 채널과 본인확인 절차를 확정했다.
- [ ] 법정 보존과 운영상 보존을 구분하고 기간 종료 후 파기 절차를 확정했다.
- [ ] Drive 휴지통 이동만으로 즉시 파기를 보장한다고 표현하지 않는다.

권장 안내:

> 성명, 계약 연락용 이메일 및 계약조건 등은 계약 체결·이행을 위해 처리합니다. 선택 동의에 근거해 처리하는 정보와 구분되며, 목적·항목·보유기간·파기방법 및 권리 행사 방법은 아래에서 확인할 수 있습니다.

## 5. 비즈니스 스폰서 정보공유

스폰서가 비용을 부담한다는 사실만으로 세션 정보의 제3자 제공 근거가 확정되는 것은 아니다.

- [ ] 스폰서 법인명과 담당자의 계약상 권한을 확인했다.
- [ ] 제공받는 자, 제공 목적, 항목, 보유기간, 동의 거부권과 영향을 별도 화면에서 제시한다.
- [ ] 참여 여부, 일정·진행률, 합의된 전체 목표, 종료 요약을 각각 선택할 수 있다.
- [ ] 세션의 구체적인 대화와 개인적인 감정·고민은 공유 선택 대상에서 제외한다.
- [ ] 공유범위 변경 시 기존 계약을 덮어쓰지 않고 새 동의 버전 또는 변경 합의서를 발행한다.
- [ ] 고객용 사본과 스폰서용 사본의 노출 항목을 구분한다.
- [ ] 스폰서용 PDF에 고객 휴대전화와 비공개 목표가 노출되지 않는다.
- [ ] 위기·법적 의무 관련 정보도 필요한 최소 범위만 공유한다.

권장 선택 동의 구조:

```text
제공받는 자: 실제 스폰서 법인명
제공 목적: 코칭 참여 및 합의된 운영현황 확인
선택 항목: 참여 여부 / 일정·진행률 / 합의된 전체 목표 / 종료 요약
제외 항목: 세션의 구체적인 대화 / 개인적인 감정·고민
보유기간: 운영 전 확정값
거부권과 영향: 선택 동의를 거부할 수 있으며 필요한 경우 운영 범위를 다시 합의
```

## 6. 전자적 체결·해지·변경

- [ ] 최종 체결 전에 금액, 기간, 환불·취소조건과 전체 계약 전문을 한 화면에서 검토할 수 있다.
- [ ] `수정`, `취소`, `전자계약 체결`을 비슷한 가시성과 난이도로 제공한다.
- [ ] 동의·비동의 버튼을 시각적으로 차별하거나 반복적으로 재유도하지 않는다.
- [ ] 체결보다 복잡한 해지 절차를 만들지 않는다.
- [ ] 성공 페이지와 완료 이메일에서 계약 관리 경로를 제공한다.
- [ ] 법정 청약철회, 일반 중도종료, 계약조건 변경, 선택 동의 철회를 서로 다른 사건으로 기록한다.
- [ ] 개인정보 권리 요청을 전자적으로 접수하고 접수증과 처리상태를 제공한다.
- [ ] 서명 토큰을 계약 관리에 재사용하지 않고 별도 단기 토큰과 이메일 확인을 사용한다.
- [ ] 스마트스토어 결제 화면의 사전 고지와 계약서의 취소·환불조건이 서로 일치한다.

Google 연동 전에는 위 계약 관리 기능의 실제 처리 백엔드가 없으므로 공개 페이지에서 완료된 전자계약 시스템으로 표시하지 않는다.

## 7. Google 처리위탁·국외이전

Google Apps Script, Sheets, Drive와 Gmail을 통한 계약 처리는 개인정보 처리위탁 및 국외 처리·보관에 해당할 가능성이 있다.

- [ ] 실제 운영 법인 또는 사업자와 Google Workspace 소유자를 확정했다.
- [ ] Google의 DPA 및 처리위탁 조건을 검토했다.
- [ ] 사용하는 Google 서비스, 재위탁자와 처리·보관 국가를 확인했다.
- [ ] 국외이전 항목·시기·방법·목적·보유기간·거부방법을 실제 값으로 고지했다.
- [ ] 개인정보처리방침에 수탁자·위탁업무 및 국외이전 현황을 반영했다.
- [ ] 운영계정 2단계 인증, 최소권한과 편집자 접근통제를 적용했다.
- [ ] 비공개 Drive 상위폴더의 공유·Shared Drive 상속 권한을 검수했다.
- [ ] 보유·파기, 침해사고 대응과 계정 상실 대응 절차를 문서화했다.
- [ ] 실제 운영계정 기반 종단간 시험을 마쳤다.

모든 항목이 확인될 때까지:

```js
electronicContractEnabled = false
```

공개 버튼 문구는 `전자계약 시스템 연결 전`으로 유지한다.

## 8. 전자문서와 증거

- [ ] 발행자, 발행시각, 계약 당사자와 역할을 고정한다.
- [ ] 전체 계약 전문과 제공자·조건 스냅샷을 고정한다.
- [ ] 계약·개인정보 안내·선택 동의의 각 버전을 저장한다.
- [ ] 이메일 OTP 인증과 성명 입력의 확인시각을 기록한다.
- [ ] 고객과 스폰서가 같은 canonical 계약 데이터의 `documentHash`를 기준으로 확인하되, 각 역할에 허용된 정보만 담은 `signerViewHash`도 별도로 검증한다.
- [ ] canonical 계약 데이터의 `documentHash`, 역할별 표시본의 `signerViewHash`, 확인증거의 `acceptanceEvidenceHash`를 서로 분리한다.
- [ ] 확인 당시의 역할별 표시본과 선택 동의 증거를 비공개 스냅샷으로 고정하고, PDF 생성 전에 각 해시를 다시 검증한다.
- [ ] 최종 PDF 생성 후 PDF 바이트의 `pdfHash`를 별도로 계산해 원장과 감사로그에 저장한다.
- [ ] PDF 안에는 자기 자신의 `pdfHash`를 넣지 않는다. 자기참조 해시는 고정될 수 없다.
- [ ] 수신·전송 실패와 재시도 기록을 계약의 법적 완료 상태와 구분한다.
- [ ] 감사로그를 관리자 편집이 가능한 기록으로 설명하고 `불변`, `위변조 불가`라고 표현하지 않는다.
- [ ] 이메일 OTP가 메일함 소유 확인이며 정부가 보증하는 본인확인이 아님을 표시한다.
- [ ] 조직 스폰서의 전자확인이 조직 대표권까지 자동으로 증명하지 않음을 검토한다.

## 9. 취소·환불·약관

- [ ] 관계 법령상 청약철회 적용 여부와 제한요건을 확인했다.
- [ ] 서비스 시작 후에도 미제공 회차를 일률적으로 `환불 불가` 처리하지 않는다.
- [ ] 가분적 서비스의 제공 회차와 미제공 부분 정산 방식을 검토했다.
- [ ] 계약·철회·결제·공급 및 불만·분쟁 기록의 법정 보존기간과 실제 적용 여부를 확인했다.
- [ ] 일정변경·노쇼·책임제한·관할 조항의 설명의무와 공정성을 검토했다.
- [ ] 단순 체크만으로 불리한 약관이 개별 협상된 조항이 된다고 가정하지 않는다.
- [ ] `어떠한 경우에도 환불 불가`를 기본값으로 사용하지 않는다.
