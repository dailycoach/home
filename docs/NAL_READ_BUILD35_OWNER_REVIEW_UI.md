# NAL READ BUILD35 — 소유자 개인정보 검토 화면, 소스 연결

실제 완료한 것은 **개발 브랜치의 화면·클라이언트 소스 구현**이다. 계정·DB·Edge 배포·공개 사이트는 이 단계에서 변경하지 않았다.

## 화면
- `/nal/read/admin/privacy/`: 기존 NalAccount 로그인과 운영 홈의 기존 `role='owner'` 응답을 재사용한다. 화면의 역할 표시는 서버 권한검사를 대체하지 않는다.
- 요청 목록: 요청 ID, 범위, 상태, 접수 시각. API 미연결은 기록 0건으로 표시하지 않는다.
- 범위 미리보기: DAY·답변·초안·실험·표시·리포트·준비·LIVE 메모의 **행 개수**, 실험·리포트에 남는 파생 사본 개수, 주문·문의·참가 내역의 별도 보존 필요성을 보여준다. 개인 성찰 원문을 표시하지 않는다.
- 명시적인 검토 시작: 현재 owner가 확인 후 `start-review`를 누르는 흐름. 이 요청은 삭제·승인과 별개이다.
- JS 호출 `NalAccount.privacyReview()`의 허용 목록: `queue`, `preview`, `start-review`. `approve-journal`·`execute-journal`·탈퇴·파기 스위치 호출은 포함하지 않았다.
- 운영 홈에는 소유자 역할에만 '개인정보 요청 검토 · 준비 중' 이동 링크를 추가했다.

## 미연결 상태
`nal-read-privacy-admin` Edge API는 아직 없다. 지난 BUILD34의 **공통 서버 인증 `p_user_id` / 관리자 RPC `p_owner_id` 불일치**를 해결하려던 권한 관련 변경이 안전 검사에서 차단됐다. 차단된 소스를 다른 경로로 우회하지 않았다. **새 화면은 비공개 소스일 뿐, 실제 운영자 데이터 조회 성공을 의미하지 않는다.**

이후 보안 검토를 통해 기존 요청마다 검증된 사용자 ID를 정확히 `p_owner_id`에 바인딩하고, DB owner 멤버십을 재확인하는 독립 기본-OFF API를 승인받아야 한다. 그 API도 검토 3동작만 허용하고 실제 파기를 노출하지 않아야 한다.

## 공개·개인정보·비용 경계
READ 공개 OFF, 저널 파기 실행 OFF, 개인정보 안내 정책 승인 없음, 실제 소유자 계정과 개인정보 요청 없음. 호스팅 전용 Draft PR #166 미변경·미병합, main 미변경. STORE/PDF, 가격, 기수 데이터, 실제 Zoom, Auth callback·키, 정책 페이지 변경 없음. 외부 API·결제·개인정보 파기 실행 없음. 새 유료 리소스 없음.

고객 로그인·브라우저·동시수정·결제·삭제 테스트는 사용자의 요청대로 **판매 직전**에 실시할 영역으로 남겨둔다. 개발 소스 반영을 기능 QA 통과로 표시하지 않는다.
