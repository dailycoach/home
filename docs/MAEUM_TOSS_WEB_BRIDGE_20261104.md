# 마음서재 ↔ 토스 한줄톡 브리지: 운영 현황 및 연결 계약 (2026-11-04)

상태: **웹측 사전점검 착수 / 운영 연동 검증 전 / 미니앱 배포 금지**.
이 문서는 코드 또는 운영 권한 확인 없이 기존 DB를 새로 만들거나 Toss 배포를 실행하는 작업지시가 아니다.

## 1. 확인된 구성 (2026-11-04)

- 구 공식 웹 소스: `dailycoach/home`의 `maeum-library/` (GitHub 접근 가능).
- 별도 공개 Sites 웹: `https://maeum-library.dailycoaching.chatgpt.site` (v4 게시 이력 확인, 해당 프로젝트의 현재 소스/서버 관리권은 이 작업 환경에서 확인 불가).
- 예전 Sites Worker/D1: `maeum-library-talk` (기존 기준 원본. `DB` D1 바인딩·실제 배포 접근은 현재 확인 불가).
- 기존 공식 웹 코드의 공개 피드: `GET https://maeum-api.daily-coach-ing.com/api/entries?limit=60` → JSON `{ok,entries}`.
- 기존 공식 웹의 관리/인증 API: `/api/participant/me`, `/api/participant/entries`, `/api/participant/entries/status`, `/api/participant/toss-exchange`. 해당 코드에 대한 과거 인수인계 문서는 있으나 운영 엔드투엔드 검증은 별개다.
- Google Sheets `마음서재 운영 DB 원장`은 **운영 미러**이지 쓰기 원본이 아니다.
- 운영 원장 `동기화설정`에는 공식 API와 '정상 운영'이 기재되어 있지만, 2026-11-04 02:20 KST에 확인한 `동기화기록` 마지막 행은 예전 URL `https://maeum-library-talk.dailycoaching.chatgpt.site/api/sheets/snapshot`의 **HTTP 404 실패**다. 설정 표시와 실데이터 로그가 충돌한다. 즉시 원인 점검 필요.

## 2. 데이터 원본 유지 원칙

- 기존 D1을 유일한 기록 원본으로 유지한다. 별도 Supabase/Sheets DB를 신설하거나 D1을 초기화/재작성하지 않는다.
- 토스 미니앱 원본 저장소, 앱 등록, 앱 수정·업데이트·실제 배포는 담당자가 별도 Codex에서 수행한다. 승인 전 미니앱 배포 금지.
- 웹은 기록을 옮겨 적지 않고 동일 서버의 공개 API만 호출한다. 참가자 개인 기록 API는 본인 인증 없이는 호출하거나 공개하지 않는다.
- 웹 브라우저에 서버 비밀값, Toss 장기 토큰, 관리자 토큰, API 서비스 키를 노출하지 않는다.

## 3. 웹 읽기 계약

**공개 읽기**: `GET /api/entries?limit=60&theme=...&q=...` (GET, 무인증).
허용되는 공개 필드 예: 기록 ID, 서가(theme), 책 제목, 저자, 본인이 공개 동의한 인용 문장, 작성일.
서버가 공개 대상을 필터링한다. 프런트에서 숨기는 것만으로는 보안이 아니다.

**공개 조건**: 작성 시 기본 비공개; 이용자의 명시적 익명 공개 동의(버전/시간 기록), 게시 가능 상태, 운영 검수/숨김 상태를 **모두** 서버에서 검사. 동의 철회 또는 운영 숨김 시 다음 공개 조회부터 즉시 제외. 비공개 개인 감상(reflection), 다음 행동(chosenStep), 이름, 전화번호, 이메일, Toss 식별/세션/기기 토큰, 연결 코드, 내부 메모는 API 반환 금지.

**웹 표시**: 문자값은 `textContent`로만 렌더링하고, 이름 대신 '익명의 마음'을 사용. 데이터가 0건이면 빈 상태를 보여준다. API 오류를 빈 목록으로 위장하지 않는다. 캐시는 `no-store` 또는 철회 시 즉시 무효화.

**본인 읽기/수정**: 참가자 인증 세션 + CSRF + 개별 레코드 소유권 확인. 공유 동의 상태 변경은 본인에게만 허용; 운영 숨김 상태에서는 재공개를 막는다.

## 4. 토스 → 서버 기록 저장 계약 (Codex 담당 경계)

- 토스 로그인/연결은 공급자 공식 검증 절차를 서버측에서 완료해 참가자에게 귀속한다. 클라이언트가 전달한 user ID를 권한 근거로 신뢰하지 않는다.
- `POST /api/participant/entries`: 인증된 참여자의 독서 기록 저장; 서버 기준 소유자, 유효성/크기 제한, 중복 재시도 방지, 단순한 개인정보 최소 수집, 기본 비공개.
- 공개하기는 쓰기/수정과 별도 명시적 선택: 동의 여부/시각/정책 버전 기록, 실패 시 비공개 유지.
- 기록 수정/삭제/비공개 철회 후 공개 피드 캐시 즉시 정리. 중복 동기화로 공개 권한이 되살아나면 안 된다.
- Toss 공유 링크/딥링크는 운영 담당자가 공식 콘솔의 현재 경로를 확인한 뒤 갱신한다. 이전에 문서화된 URL을 검증 없이 믿지 않는다.

## 5. 금번 발견된 차단 사항

1. **긴급**: 15분 Apps Script 트리거가 예전 Sites 주소를 호출해 404 로그를 반복 생성한다. Google Apps Script 실행 권한이 확보되면 우선 실패 트리거를 중단하고, 공식 API의 인증/SSL/라우팅을 실제 검증한 다음에만 URL 교체 후 재개한다. 시트 셀의 `동기화설정` 변경은 실제 스크립트 속성/트리거 변경을 대신하지 못한다.
2. **중요**: 현재 공개 Sites v4 프로젝트 소스/Worker/D1 바인딩과 기존 `maeum-library-talk`의 관계가 확인되지 않았다. 단순히 도메인을 바꾸면 안 된다.
3. **중요**: `maeum-api.daily-coach-ing.com`의 운영 HTTP 상태/CORS/인증 테스트를 이 실행 환경에서 직접 확인하지 못했다.
4. **중요**: 토스 미니앱 최신 소스/등록 상태는 여기서 직접 확인되지 않아 쓰기/실사용 테스트 불가.

## 6. 이어서 필요한 정확한 접근

- 새 Sites 프로젝트 `maeum-library`의 최신 v4 소스 편집 접근(웹 한줄톡 렌더링 대상 확인).
- 기존 `maeum-library-talk` Sites 프로젝트의 Worker 소스/실제 배포/기존 D1 `DB` 바인딩에 대한 **읽기/수정** 접근. 새 DB는 만들지 않는다.
- Cloudflare DNS/SSL 및 공개 API 라우트 상태 조회 접근. 비밀키를 채팅/문서로 제출하지 않는다.
- 운영 원장에 묶인 Google Apps Script의 속성명/트리거/실행 로그 조회·중지 권한(비밀값 자체는 출력 금지).
- Codex 담당 측의 최신 토스 미니앱 API 호출 형식/검수 상태 보고(앱 소스 병합이나 직접 배포 요청 아님).

## 7. 승인 기준 (운영 데이터 변조 없는 테스트)

1. 공통 API `/api/entries` 200, JSON `{ok:true,entries:[]}` 형식, CORS 허용.
2. 무인증 `/api/participant/me` 401, 토큰 없는 `/api/sheets/snapshot` 401/403.
3. 공개 결과에 비공개 본문/연락처/식별자/토큰 없음. 공개 조건 서버측 적용.
4. 동의하지 않은 기록은 0건 공개. 공개 동의한 기록만 표시.
5. 공개 철회/운영 숨김 후 즉시 미노출 (검증용 격리 데이터 또는 허가된 테스트 계정만).
6. Toss 작성 → 기존 D1 단일 원본 저장 → 웹 한줄톡 조회의 end-to-end 통과.
7. Google Sheets 수동 동기화 1회 성공, 자동 연속 2회 성공 이후 단일 트리거만 활성화.
8. 기존 공개 데이터 및 개인정보 보존, 미니앱 승인 전 배포 없음.

### 읽기 전용 진단

`node scripts/check-maeum-toss-web-bridge.mjs`

수정이나 데이터 생성 없이 HTTP 상태와 공개 피드의 필드 누출 여부만 검사한다. 실행 실패를 '통합 실패'로 일반화하지 말고 네트워크/권한/라우트 문제로 분류한다.
