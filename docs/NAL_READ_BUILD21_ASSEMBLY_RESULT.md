## 비용·변경 범위

표준 `ubuntu-24.04` 실행기만 사용했고, 공개 저장소 조건을 만족할 때만 작업하도록 제한했습니다. 과금 가능한 별도 Actions 아티팩트 업로드나 캐시 저장은 사용하지 않았습니다. 결과는 기존 Git 저장소의 전용 브랜치에 보관했습니다. 새 서버·유료 SDK·AI API·결제 서비스·구독을 만들지 않았습니다.

기존 개발 커밋은 `[skip ci]`를 유지하며, 새 작업은 지정한 통합 브랜치 생성 이벤트에서 소스 조립만 수행했습니다. 기존 테스트·배포 워크플로는 수정하거나 실행 명령을 넣지 않았습니다. main이나 개발 브랜치로 결과물을 자동 병합하지 않았습니다.

워크플로는 GitHub 체크아웃과 생성물 push를 위해 GitHub 네트워크를 사용했습니다. 그 안에서 실행한 오프라인 조립기 자체의 네트워크 요청은 0이며, DB·결제사·사용자 서비스에 연결하지 않았습니다. 두 범위를 혼동해 전체 작업이 네트워크 없이 실행됐다고 표현하지 않습니다.

## 아직 하지 않은 것

통합 SQL 적용, Supabase 서버 함수 배포, 실제 프런트엔드 반영, Auth callback 및 환경 설정, 첫 기수 생성·공개, 결제 활성화, 실제 참가자 기록 생성, 판매 전 QA는 하지 않았습니다. 기존 앱 소스·가격·모집일·정원·첫 시즌 원고·무료 PDF·결제 및 환불 로직도 이번 BUILD21에서 수정하지 않았습니다.

통합 SQL은 기반 조건이 달라지거나 부분 적용 상태이면 중단하도록 조립된 후보입니다. 생성 성공은 PostgreSQL에서의 문법·권한·업무 흐름 검증이 아닙니다. 실제 적용 전에 대상 이력과 스키마를 확인해야 하며, 기존 STORE 이력 식별자 차이는 여전히 별도 조정 항목입니다.

`public-overlay`는 기존 웹사이트에 반영할 범위입니다. ZIP 전체나 `private` 폴더를 웹 루트에 올리지 않습니다. 기존 무료 PDF·이미지·폰트·실제 연결 설정을 삭제하는 동기화 방식도 사용하지 않습니다. 이 저장소는 공개 저장소이며 `private`는 웹 루트에서 제외하라는 분류명이지 저장소 비공개 보장을 의미하지 않습니다.
