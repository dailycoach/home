## 0. 선택 위치 핫픽스 재검수

사용자가 보고한 “선택할 때마다 화면이 상단으로 이동” 현상을 우선순위 1로 두고 선택·필터·방향 전 구간을 다시 점검했다.

| 검수 항목 | 결과 | 확인 내용 |
|---|---:|---|
| 선택 후 스크롤 위치 | PASS | 렌더 전 `scrollY`와 클릭 카드의 화면상 Y 좌표를 저장하고 렌더 후 같은 위치로 복원 |
| 선택 후 키보드 포커스 | PASS | 교체된 동일 카드에 `focus({ preventScroll: true })` 적용 |
| 단계 이동 위치 | PASS | START/NEXT/BACK/EDIT에서만 의도적으로 상단 이동, `<main>`에 포커스 이동 |
| 선택 제한 초과 | PASS | 제한 초과 시 재렌더하지 않고 안내 토스트만 출력 |
| 날짜 범위 | PASS | 한국 시간 기준 오늘부터 D+7까지 허용, D+8 및 잘못된 날짜 형식 차단 |
| 결과 WORD PULSE | PASS | `NEEDS ROOM`과 `ALREADY ALIVE`가 가능한 경우 서로 다른 단어를 출력 |
| 한국어 조사 | PASS | 받침 유무에 따라 이/가, 을/를 자동 적용 |
| 접근성 실시간 알림 | PASS | 전체 `<main>`의 live region을 제거하고 짧은 토스트만 `aria-live` 유지 |
| 색상 대비 | PASS | 파랑/웜화이트 5.24:1, 회색/웜화이트 4.73:1로 WCAG AA 충족 |
| 인쇄 레이아웃 | PASS* | 축소 변환 제거, A4 여백·포스터 밀도·페이지 분할 방지 규칙 적용 |

핫픽스 함수 검증 16개, 선택 렌더 계약 6개, 데이터 균형, JavaScript 구문, diff whitespace 검사를 모두 통과했다. `PASS*` 항목은 코드와 인쇄 규칙 기준이며 실제 프린터 드라이버별 A4 미리보기는 배포 주소에서 마지막으로 확인한다.

## 2. 전체 흐름 회귀 테스트

다음 실제 이벤트 흐름을 DOM 환경에서 끝까지 실행했다.

`COVER → COACH/일과 역할 → PICK 18 → CUT 10 → KEEP 5 → NOT THIS 5 → BUT THIS 2 → REAL SCENE → CLASH → THIS WEEK → RESULT → COPY/PRINT → 저장 후 재진입`

결과: 전 단계 통과, 콘솔 오류 0건.

## 3. 반응형·인쇄 검수

- 1040px, 760px, 380px 분기 규칙 적용
- 모바일 가치 카드 2열, 초소형 화면 1열 전환
- 주요 선택 버튼 최소 높이 42~52px 확보
- 결과 포스터 모바일 재배열 적용
- `prefers-reduced-motion` 대응
- A4 세로 인쇄 시 헤더·진행바·보조 카드 제외, 결과 포스터 중심 출력

## 4. 남은 운영 확인

클라우드 브라우저 보안 정책이 로컬 주소와 GitHub 브랜치 미리보기 주소를 차단해 핫픽스 브랜치의 실제 픽셀 스크린샷 검수는 완료하지 못했다. 기존 운영본의 전체 사용자 흐름과 핫픽스 코드·상태 전환·검증 규칙은 통과했으며, 운영 반영 직후 다음 5가지를 최종 육안 확인한다.

1. 390px 모바일 첫 화면에서 `WHAT STAYS?` 줄바꿈
2. 외부 웹폰트 로딩 실패 시 폴백 타이포의 밀도
3. 결과 포스터 전체 화면 캡처 시 하단 잘림 여부
4. 브라우저 인쇄 미리보기에서 A4 1페이지 수렴 여부
5. 모바일 중하단 카드 선택 전후 화면 위치와 포커스 유지 여부
