# NAL READ · BUILD20 통합 조립과 참가자 진입점

## 현재 전달 상태

BUILD20은 **통합 조립기·실제 DB 기반 관찰 기록·기존 참가자 주소 연결 코드**입니다. 조립기 전체 실행, 최종 ZIP 생성, DB 적용, API 배포와 판매 전 테스트는 아직 하지 않았습니다. 이 문서나 소스가 있다고 실행 완료로 표시하지 않습니다.

이번 작업에서는 연결된 `nal-platform`의 마이그레이션 이력·테이블 목록·기반 함수 정의의 해시와 READ 공개 모드만 읽었습니다. 참가자 답변·문의 본문·결제 상세·비밀번호는 읽지 않았고, 데이터를 변경하지 않았습니다. 2026년 10월 7일 관찰 범위에서 READ 이력은 FIX03까지 기록돼 있었고 공개 모드는 `off`였습니다. 이는 새 기능의 정상 동작 검사 결과가 아닙니다.

관찰 기록은 `baseline-observation.json`입니다. 저장소의 디지털 스토어 기반 파일 식별자와 실제 DB 이력 식별자가 다른 부분도 따로 남겼습니다. 이름이 비슷하다고 같은 SQL이라고 판단하거나, 이력을 보정하거나, 기반을 다시 실행하지 않습니다.

## 참가자 기존 주소 8개를 공통 화면으로

BEFORE·TODAY·JOURNEY·DAY·TRY·LIVE·내 문장·리포트의 기존 `/nal/read/trend-2027/.../` 주소는 공통 `/nal/read/open/` 화면으로 연결됩니다. 기존 주소에서 예전 계정 모듈과 편집기를 먼저 실행하지 않습니다.

시즌과 화면 종류는 고정된 해당 경로에서 결정합니다. DAY와 질문 위치, TRY의 주차·실험 ID, LIVE의 주차·일정 ID는 정해진 범위 안에서 이어갑니다. 다른 시즌, 중복 위치 정보, 잘못된 ID를 발견하면 다른 기록으로 대신 열지 않습니다. 인증 토큰·결제 응답·알 수 없는 본문 정보는 새 주소로 전달하지 않습니다. 로그인 및 결제 콜백 화면은 이번 변경 대상이 아닙니다.

주소 이동은 참가권을 만들거나 공개되지 않은 질문을 열어주는 기능이 아닙니다. 도착한 공통 화면은 기존 로그인·공개 범위·소유권 규칙을 그대로 사용합니다. 브라우저에 남은 이전 캐시는 실제 배포 시 별도로 정리해야 하며, 이번 코드 변경이 이미 서비스 캐시를 비웠다는 뜻은 아닙니다.

## 조립기 사용 — DB에 연결하지 않는 로컬 빌드

BUILD20이 커밋된 로컬 저장소에서 사용합니다. Python 3.10 이상과 Git만 사용하며 설치·원격 다운로드·테스트 명령·DB 접속 기능은 없습니다.

```sh
python scripts/assemble-nal-read-build20.py \
  --source-commit "$(git rev-parse HEAD)" \
  --out ../nal-read-build20-integration
```

`--source-commit`은 BUILD20 조립기 자체를 포함한 완전한 커밋 SHA여야 합니다. 조립기는 실행 중인 파일과 지정한 커밋의 도구 원문을 비교하고, 기존 BUILD19가 선행하는지 확인합니다. 변경 중인 작업 폴더의 코드나 비밀 설정을 몰래 포함하지 않습니다. 필요한 Git 객체가 없으면 멈추며 자동 fetch는 하지 않습니다.

출력 폴더는 저장소 밖의 새 폴더여야 합니다. 기존 폴더를 덮어쓰지 않습니다. 성공하도록 구현한 출력은 다음과 같습니다.

```text
public-overlay/nal/...                  웹에 반영할 추가·수정 파일만
public-overlay/nal/data/read-release.json 버전 정보만; 연결 설정 아님
private/edge/supabase/functions/...      같은 커밋의 서버 함수 소스
private/database/after-fix03.forward.sql 통합 적용 후보 SQL
private/database/original-layers/...    19개 원문을 그대로 보존
private/database/LAYERS.json            원문 해시와 제거한 외곽 경계 위치
private/database/baseline-observation.json 읽기 전용 기반 관찰 기록
private/editorial-input/...             원고 입력; 저장·승인·공개 아님
private/reference/...                   공통 스타일·PDF 경계의 참고 소스
private/ASSET-TRANSFORMATIONS.json       화면 파일의 버전 표기 변경 내역
ASSEMBLY.json                           실행됐을 때의 조립 결과
FILE-INVENTORY.json                     원본·출력 파일의 해시
CHECKSUMS.sha256                        파일 동일성 정보
nal-read-build20-<commit>.zip            위 내용을 담는 비공개 인계 묶음
```

## DB 원문 19개를 한 트랜잭션 후보로

BUILD19가 보존용 원문 묶음이었다면, BUILD20은 그 원문에서 **한 번에 적용할 전진 변경 후보**를 조립합니다. 원본 SQL 파일은 수정하지 않습니다.

단순한 문자열 치환으로 `BEGIN`과 `COMMIT`을 지우지 않습니다. 따옴표·달러 인용 함수 본문·주석을 건너뛰어 최상위 문장 경계를 찾고, 파일 맨 앞과 맨 뒤의 정확한 외곽 트랜잭션 두 문장만 제거합니다. 함수 내부의 `BEGIN/END`와 SQL 본문은 보존합니다. 예상과 다른 문장 구성이면 중단합니다.

이후 기반 조건문, 순서가 정해진 19개 변경 본문, 비공개 통합 버전 함수를 하나의 `BEGIN … COMMIT` 안에 넣습니다. 실제 적용 시 중간 SQL이 실패하면 그 트랜잭션이 완료되지 않도록 하는 구성입니다. 이것은 아직 PostgreSQL에서 실행해 확인한 결과가 아니며, 문장 경계 분석도 SQL의 타당성이나 업무 로직 검사를 대신하지 않습니다.

후보 SQL은 다음 조건에서 멈추도록 작성했습니다.

- 의도한 FIX03 초기 통합 프로필과 정확한 소스 커밋을 별도로 확인하지 않은 경우.
- 관찰한 PostgreSQL 17 기반, 필요한 READ 이력 또는 함수 7개의 정의가 다른 경우.
- READ 공개가 `off`가 아니거나, 이미 BUILD 추가 테이블·계정 래퍼·참가 등록이 있는 경우.
- 이 통합본이 이미 적용된 경우.

프로필·소스 설정은 실수 방지를 위한 운영자 확인 값이지 실제 서버 신원을 증명하는 인증 수단이 아닙니다. 검토하지 않은 운영 DB에 적용할 근거로 사용하지 않습니다. 함수 해시 역시 일부 변경 감지용이며, 전체 스키마 동등성이나 보안 검토 완료를 뜻하지 않습니다.

생성된 `.forward.sql`은 **마이그레이션 이력에 등록되지 않은 후보 파일**입니다. CLI로 새 마이그레이션을 만들고 대상에 맞추는 실제 적용 단계는 별도입니다. 조립기는 적용·이력 보정·rollback SQL 실행을 하지 않습니다.

## 화면과 API 버전 맞추기

공개 파일과 서버 소스는 같은 입력 커밋에서 꺼냅니다. 공개 파일 안의 포함 대상 CSS/JavaScript 참조, 상대 모듈 import, 기존 동적 로더의 빌드 표기를 `build20-<commit>`으로 맞추도록 작성했습니다. 변환 전후 해시는 구분해 남깁니다.

이 방식은 Auth 요청을 가로채거나 브라우저의 fetch를 바꾸지 않습니다. 서버 API·인증·환불 로직도 재작성하지 않습니다. 생성된 화면 파일과 같은 버전의 서버 함수를 함께 인계할 수 있도록 모으는 것입니다. 임의 문자열로 계산하는 모든 가능한 URL을 추론하는 범용 번들러는 아니며, 이 저장소의 현재 고정 참조와 로더 형식을 대상으로 합니다.

실제 backend JSON, 서버 키, gateway 설정, Origin, Auth callback과 결제사 설정은 포함하지 않습니다. BUILD19 runtime 참고표는 함수 대응 관계용이며, 실제 인계 버전은 BUILD20의 `runtime-version.json`과 `ASSEMBLY.json`을 따릅니다.

## 공개 파일과 비공개 파일은 섞지 않습니다

웹에 반영하는 범위는 `public-overlay`뿐입니다. 기존 스토어·무료 PDF·이미지·폰트·실제 연결 설정은 기존 호스트에 보존합니다. 새 폴더에 없는 파일을 삭제하는 방식으로 덮어쓰지 않습니다.

`private`와 ZIP 전체는 공개 웹 루트에 올리지 않습니다. PDF webhook 참고 파일 한 개만 별도로 배포하거나 기존 receiver를 교체하지 않습니다. 실제 참가자·기수·승인·테스트 데이터를 만들거나, 새로운 과금 리소스를 여는 단계도 포함하지 않습니다.

## 아직 남은 경계

이번 실행 환경에서는 전체 저장소 다운로드가 불가능해 조립기를 실제 원본 전체에 실행하지 않았습니다. 따라서 최종 SQL·ZIP·파일 수·생성 해시는 아직 산출 결과로 보고하지 않습니다. 새 경로 코드도 브라우저 테스트를 실행하지 않았습니다.

현재 결과는 개발 브랜치의 구현과 제한된 DB 기반 관찰입니다. 최종 조립 실행, 대상별 전체 스키마 확인, API·공개 파일의 실제 반영, 최초 기수 입력, 고객 판매 직전 테스트는 별도 단계입니다. 운영 서버 적용이나 판매 활성화가 완료됐다는 뜻이 아닙니다.
