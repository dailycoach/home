# NAL Image Shooting Guide

NAL의 이미지는 실제 모임, 실제 활동, 실제 도구와 실제 진행자를 기록한다. 이미지가 준비되지 않았으면 UI의 의도된 빈 상태를 사용하며 무단 이미지나 생성형 AI 이미지로 자리를 채우지 않는다.

## 1. 공통 촬영 원칙

- 자연광을 기본으로 하고 필요한 경우 약한 직광 플래시로 편집숍 같은 질감을 더한다.
- 과도하게 연출된 상담실 장면보다 사람들이 도구를 쓰고 대화하는 자연스러운 순간을 촬영한다.
- 한 세트에서 전체 공간, 상호작용, 손과 도구, 결과물, 진행자 장면을 함께 확보한다.
- 얼굴과 손의 형태가 자연스럽고 도구의 글자·색이 실제와 일치해야 한다.
- 프레임 중앙 70%에 핵심 피사체를 두어 모바일·데스크톱 크롭에 대응한다.
- 이미지 안에 제목, 가격, 일정, 로고를 합성하지 않는다. 정보는 HTML 텍스트로 제공한다.
- 노출, 화이트밸런스, 수평, 크롭과 먼지 제거 수준의 일반 보정만 허용한다.
- 생성형 AI 이미지, AI 인물, 생성형 채우기, 합성 참석자와 실제에 없는 상품 구성은 사용하지 않는다.
- SNS 캡처, 검색 이미지, 워터마크 이미지, 구매·사용 허가가 불명확한 스톡 이미지는 사용하지 않는다.

## 2. 동의와 개인정보

- 얼굴을 식별할 수 있는 참여자는 촬영 동의와 공개 채널·기간을 사전에 확인한다.
- 프로그램 참여 동의와 사진·영상 공개 동의는 분리한다.
- 미성년자는 보호자의 명시적 동의 없이는 촬영·공개하지 않는다.
- 동의하지 않은 참여자는 뒷모습만 찍는 것으로 대신하지 말고 프레임에서 제외한다.
- 이름, 연락처, 신청 명단, 워크북의 개인 기록과 화면 알림이 보이지 않게 한다.
- 작품과 후기에도 개인 경험이 포함될 수 있으므로 제작자에게 별도 공개 동의를 받는다.
- 배포 파일에서 GPS 등 불필요한 EXIF 정보를 제거한다.

## 3. 카테고리별 촬영 명세

### 3.1 NAL GATHER

| 항목 | 기준 |
|---|---|
| 핵심 장면 | 4~8명이 한 테이블이나 열린 공간에서 실제로 대화하고 듣는 장면 |
| 보조 장면 | 손과 카드, 참여자가 원을 이루는 배치, 공간 전경, 함께 정리하는 순간 |
| 배제 | 상담자와 내담자가 마주 보는 2인 상담 연출, 카메라를 향한 단체 포즈만 있는 세트 |
| 카드 비율 | 4:3 |
| 권장 원본 | 가로 2400×1800px 이상 |
| 웹 출력 | 1600×1200, 960×720, 640×480 |
| 파일명 | `gather-{slug}-cover-v01.webp`, `gather-{slug}-gallery-01-v01.webp` |

구도는 사람 사이의 거리와 참여 방식이 보이게 잡는다. 특정 한 사람만 주인공처럼 보이거나 참여자의 표정을 감정 상태로 단정할 수 있는 클로즈업은 피한다.

alt 예시: `둥근 테이블에 앉아 감정카드를 살펴보며 대화하는 참여자들`

### 3.2 NAL CLASS

| 항목 | 기준 |
|---|---|
| 핵심 장면 | 활동 과정이나 완성 결과물이 먼저 보이고 참여자의 손이 자연스럽게 들어오는 장면 |
| 보조 장면 | 재료 준비, 진행자의 시범, 개인 작업, 테이블 위 결과물, 공간 안내 |
| 배제 | 실제 제공하지 않는 재료, 완성품을 과장한 연출, 모든 참여자가 동일한 결과를 만든 것처럼 보이는 장면 |
| 카드 비율 | 5:4 |
| 상세 히어로 | 4:3 |
| 권장 원본 | 가로 2500×2000px 이상, 상세용은 2400×1800px 이상 |
| 웹 출력 | 카드 1600×1280 / 1000×800 / 625×500, 상세 1600×1200 / 960×720 |
| 파일명 | `class-{slug}-cover-v01.webp`, `class-{slug}-detail-01-v01.webp` |

원데이클래스는 무엇을 하는지 한눈에 보여야 한다. 인물 사진보다 활동과 결과물이 우선이며, 그림 실력이나 심리 상태를 평가하는 인상을 주지 않는다.

alt 예시: `색연필과 색종이로 현재의 마음을 표현하는 참가자의 손과 스케치북`

### 3.3 NAL SHOP

| 항목 | 기준 |
|---|---|
| 핵심 장면 | 상품 정면 또는 45도 제품 클로즈업, 실제 구성품 전체가 보이는 플랫레이 |
| 보조 장면 | 패키지 앞·뒤, 카드 펼침, 크기 비교, 개인·커플·모임 사용 장면, 포장 상태 |
| 배경 | Warm Ivory 또는 Clean White 계열의 무광 배경, 제품 색과 구분되는 단순 소품 |
| 배제 | 구성에 포함되지 않는 소품을 구성품처럼 배치, 카드 문구 합성, 실제보다 많은 수량 연출 |
| 카드·갤러리 비율 | 1:1 |
| 권장 원본 | 2400×2400px 이상 |
| 웹 출력 | 1600×1600, 960×960, 640×640 |
| 파일명 | `shop-{slug}-cover-v01.webp`, `shop-{slug}-components-v01.webp`, `shop-{slug}-usage-01-v01.webp` |

제품 촬영 전 그레이카드로 화이트밸런스를 맞추고 카드·워크북의 실제 색과 글자 가독성을 유지한다. 미리보기에서 개인정보나 공개 불가 문항이 노출되지 않는지 확인한다.

alt 예시: `아이보리 테이블 위에 펼쳐 놓은 감정카드 패키지와 실제 구성 카드`

### 3.4 NAL NOTE

| 항목 | 기준 |
|---|---|
| 핵심 장면 | 글의 주제를 보여주는 도구·장소·손의 기록 또는 실제 프로그램 현장 디테일 |
| 보조 장면 | 메모, 카드 사용 순서, 작품의 일부, 진행자 인터뷰 환경 |
| 배제 | 내용과 무관한 감성 스톡 사진, 전형적인 명상 포즈, 의미 없는 태양·전구·별·반짝이 이미지 |
| 카드 비율 | 16:9 |
| 권장 원본 | 가로 2400×1350px 이상 |
| 웹 출력 | 1600×900, 960×540, 640×360 |
| 파일명 | `note-{slug}-cover-v01.webp`, `note-{slug}-inline-01-v01.webp` |

관련 사진이 없으면 억지로 이미지를 만들지 않고 타이포그래피 중심 카드로 둔다. 사진 위에 글 제목을 넣지 않는다.

alt 예시: `감정카드 한 장을 고르고 기록지에 문장을 적는 손`

### 3.5 NAL HOST

| 항목 | 기준 |
|---|---|
| 핵심 장면 | 진행자의 눈과 얼굴이 선명한 상반신 환경 인물 사진 |
| 보조 장면 | 실제 프로그램 진행, 도구 설명, 참여 공간을 준비하는 모습 |
| 배경 | 진행 분야가 드러나는 실제 서재·작업 공간·클래스 공간. 배경은 인물보다 한 단계 어둡거나 부드럽게 처리 |
| 배제 | 과도한 피부 보정, 얼굴형 변경, 가짜 자격·브랜드 소품, 상담실 악수 포즈 |
| 실제 노출 비율 | 1:1 |
| 촬영 원본 | 세로 4:5와 가로 환경 컷을 함께 촬영, 긴 변 2400px 이상 |
| 웹 출력 | 정사각 1200×1200, 720×720, 480×480 |
| 파일명 | `host-{slug}-profile-v01.webp`, `host-{slug}-session-01-v01.webp` |

정사각형과 모바일 크롭에서도 눈·턱·머리끝이 잘리지 않도록 머리 위와 양옆에 여유를 둔다. 프로필 사진의 배경만으로 자격이나 기관 소속을 암시하지 않는다.

alt 예시: `책과 미술 작품이 있는 공간에 선 박지아 코치의 상반신 프로필`

## 4. 히어로·공유 이미지

| 용도 | 비율 | 권장 출력 | 파일명 |
|---|---:|---:|---|
| 홈 대표 모집 히어로 | 4:3 원본을 넓게 크롭 가능하게 촬영 | 2000×1500px | `home-feature-{program-slug}-v01.webp` |
| 프로그램 상세 히어로 | 4:3 | 2000×1500px | `{type}-{slug}-hero-v01.webp` |
| Open Graph | 1200:630 | 1200×630px | `og-{page-or-slug}-v01.webp` |

히어로는 모바일에서 좌우가 잘릴 수 있으므로 얼굴, 손, 상품명을 가장자리 15%에 두지 않는다. Open Graph 이미지의 핵심 텍스트와 로고는 사방 80px 안전 영역 안에 둔다.

## 5. 파일·폴더 규칙

권장 배포 구조:

```text
nal/assets/images/
├── gather/{slug}/
├── class/{slug}/
├── shop/{slug}/
├── note/{slug}/
└── host/{slug}/
```

파일명은 소문자 영문·숫자·하이픈만 사용한다.

```text
{section}-{slug}-{role}-{sequence}-v{version}.{format}
```

- `role`: `cover`, `hero`, `gallery`, `components`, `usage`, `profile`, `session`, `inline`
- `sequence`: 여러 장일 때 `01`, `02`처럼 두 자리 사용
- `version`: `v01`, `v02`처럼 증가
- 같은 이미지를 교체할 때 캐시 갱신이 필요하면 버전을 올리고 JSON 경로도 함께 바꾼다.
- 한글, 공백, 괄호, 날짜만 있는 이름과 `final-final` 같은 이름은 사용하지 않는다.

## 6. WebP·AVIF 출력

- 색공간은 sRGB로 통일한다.
- 사진의 기본 폴백은 WebP다. 현재 JSON의 `coverImage`와 `gallery`에는 실제로 표시 가능한 WebP 경로를 우선 등록한다.
- AVIF는 같은 basename으로 함께 만들 수 있으나, `<picture>`와 `srcset`이 실제 구현된 화면에서만 제공한다. 사용하지 않는 AVIF를 단순 적재하지 않는다.
- 권장 시작값: WebP quality 78~84, AVIF quality 45~55. 글자가 있는 카드 미리보기는 눈으로 확인해 압축률을 낮춘다.
- 카드·목록 이미지는 장당 약 250KB 이하, 상세 히어로는 약 450KB 이하를 목표로 하되 얼굴·제품 글자가 깨지면 품질을 우선한다.
- 크기가 지정된 `<img>`에는 `width`와 `height`를 함께 제공해 레이아웃 이동을 줄인다.
- 첫 화면 대표 이미지는 지연 로딩하지 않고, 화면 아래 이미지는 `loading="lazy"`와 `decoding="async"`를 사용한다.
- 반응형 이미지 지원 시 640, 960, 1600px 파생본을 `srcset`으로 연결한다.

AVIF와 WebP를 모두 납품하는 예:

```text
class-art-current-mind-cover-v01.avif
class-art-current-mind-cover-v01.webp
class-art-current-mind-cover-640-v01.webp
class-art-current-mind-cover-960-v01.webp
```

## 7. alt 작성 기준

alt는 파일명이나 마케팅 문구가 아니라 화면에서 전달하는 실제 시각 정보를 짧게 설명한다.

- 누가, 무엇을, 어떻게 하고 있는지 1문장으로 쓴다.
- `사진`, `이미지`, `보여주는`으로 시작하지 않는다.
- 보이지 않는 감정, 성격, 진단, 관계 상태를 추정하지 않는다.
- `힐링되는`, `치유하는`, `행복한`, `우울한`처럼 표정이나 효과를 단정하지 않는다.
- 상품 alt에는 보이는 구성과 배치를 쓰고 치료·개선 효과를 넣지 않는다.
- 인물 이름은 공개 동의가 있고 인물 식별이 콘텐츠 목적일 때만 쓴다.
- 주변 본문이 같은 정보를 완전히 설명하는 장식 이미지는 `alt=""`로 둔다.
- 동일 사진을 다른 맥락에서 쓰면 그 화면에서 필요한 정보에 맞춰 alt를 조정한다.

좋은 예:

- `세 사람이 테이블에 놓인 질문카드를 고르며 대화하는 장면`
- `감정카드 40장을 색상별로 펼쳐 놓은 실제 구성`
- `작품을 가리키며 활동 순서를 설명하는 진행자`

피해야 할 예:

- `NAL 이미지`
- `힐링하는 행복한 사람들`
- `우울증을 개선하는 감정카드`
- `image_001_final.webp`

## 8. 납품 전 체크

- [ ] 촬영·작품·인물 공개 동의가 확인되었다.
- [ ] 무단 이미지와 생성형 AI 이미지가 없다.
- [ ] 실제 제공 내용과 사진 속 구성품이 일치한다.
- [ ] 얼굴, 손, 카드 글자와 제품 색이 자연스럽다.
- [ ] 모바일·데스크톱 크롭에서 핵심 피사체가 잘리지 않는다.
- [ ] WebP 폴백이 있고 필요한 화면에만 AVIF를 연결했다.
- [ ] 파일명과 slug가 데이터와 일치한다.
- [ ] 모든 정보성 이미지 alt가 실제 장면을 설명한다.
- [ ] EXIF 위치정보와 화면 속 개인정보를 제거했다.
- [ ] 이미지 크기, 압축 품질과 깨짐을 실제 브라우저에서 확인했다.
